- **Dependency**: CPU fallback
- **AR**: Verify

## action_TBD

* Verify fix from merged PR [intel/torch-xpu-ops#3018](https://github.com/intel/torch-xpu-ops/pull/3018) and close

## action_reason

* PR intel/torch-xpu-ops#3018 is a verified fixing PR for SparseCsrXPU sampled_addmm and is now merged.

## Root Cause

aten::sparse_sampled_addmm has no SparseCsrXPU registration, so all test_sampled_addmm_* and
gradcheck_mm_SparseCSR_* tests raise NotImplementedError on the SparseCsrXPU backend. Additionally,
sample input creation via .to_sparse_csr() raises 'expected col_indices to be a contiguous tensor
per batch', indicating XPU CSR conversion path is also broken. No kernel exists under
third_party/torch-xpu-ops/src/ATen/native/sparse/.

## Fix Approach

- - - - Either register a CPU fallback for aten::sparse_sampled_addmm on SparseCsrXPU (analogous to other sparse fallbacks in torch-xpu-ops/src/ATen/native/sparse/) and fix to_sparse_csr contiguity for XPU, or implement a native SYCL sampled_addmm CSR kernel. - Skip UTs in skip_list_common.py until coverage lands.
