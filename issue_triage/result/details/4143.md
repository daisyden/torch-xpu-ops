## Root Cause

~30% first-token latency regression after upgrading transformers 5.9.0 -> 5.13.0-dev on TorchAO
quantized LLM inference (Qwen3-4B, Qwen2.5-1.5B). Indicates an external-stack behavior change (model
graph, attention/cache handling, or generation defaults) increasing overhead or altering
fusion/compile friendliness for the TorchAO path. Trigger is a transformers version bump, no
internal PyTorch-only change cited, so the primary cause is the upstream transformers integration
surface, not a standalone TorchAO kernel regression.

## Fix Approach

- Bisect transformers between 5.9.0 and 5.13.0-dev with a fixed repro and identical TorchAO/PyTorch settings.
- diff generated model graphs and first-token paths (prefill, KV-cache update, attention impl, dtype/quant wrappers).
- Capture torch.compile/inductor artifacts + per-op profiling to find which new ops/graph breaks account for the 30% delta.
- add a TorchAO-compatible workaround (or pin/guard the transformers behavior) and upstream a fix/report to transformers with the minimized repro.
