## Root Cause

XPU SDPA FlashAttention explicitly hard-limits head_dim to 192 in the capability gate, so
`head_dim=256` is rejected before kernel launch. The check is implemented in
`aten/src/ATen/native/transformers/xpu/sdp_utils.cpp:108-120` (`max_supported_headdim = 192`), and
`can_use_flash_attention` enforces it as a required constraint
(`aten/src/ATen/native/transformers/xpu/sdp_utils.cpp:165-181`). This matches the user-observed `No
available kernel` when forcing FLASH_ATTENTION backend.

## Fix Approach

- Raise/extend the head-dim limit in upstream XPU flash-attention capability and kernel support path (including backward) to cover 256, then add targeted SDPA tests for `head_dim=256` with causal+GQA on XPU.
- If full kernel support is not ready, improve dispatch diagnostics and ensure graceful fallback when FLASH_ATTENTION is forced is documented clearly.
