## Root Cause

The slowdown is in the torch.compile Inductor path for small MXFP8 quantization shapes, where
decomposed quantization patterns generate Triton-backed XPU kernels instead of the fused vLLM
kernels. XPU Inductor uses Triton by default at torch/_inductor/config.py:2635 and delegates XPU
scheduling to TritonScheduling in torch/_inductor/codegen/xpu/xpu_combined_scheduling.py:44, while
benchmark overhead modeling still has a launch-overhead TODO at
torch/_inductor/runtime/benchmarking.py:676. For M=1..128, fixed Triton launch/codegen overhead
dominates the small tensors, matching the issue's measured Inductor/fused ratios above 1.

## Fix Approach

- Profile the reproducer by pattern and launch count, then add small-shape XPU heuristics/fusion for MXFP8 quantization patterns or route them to fused Triton kernels.
- Coordinate with intel-xpu-backend-for-triton issue 7048 and update Inductor overhead modeling so small-M choices account for launch latency.
