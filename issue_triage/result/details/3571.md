## Root Cause

The failing tests are Dynamo stream-tracing tests in
third_party/torch-xpu-ops/test/xpu/dynamo/test_streams_xpu.py that compare print_graph output
against inline stream annotations, for example test_stream_enter_exit expects streams 0 and 1 at
lines 73-88, while record/dealloc and backward tests also assert hard-coded stream/event indices at
lines 562-603, 732-758, and 990-1004. Those stream annotations come from PyTorch's symbolic stream
registry: SymbolicStreamState resets tracking and registers the current stream as index 0 at
torch/_dynamo/variables/streams.py:271-291, and StreamContextVariable emits the stored
user_object_index at lines 336-342. The bug is therefore not an aten operator failure; it is brittle
upstream Dynamo stream-id text expectations/registration semantics surfacing differently on XPU.

## Fix Approach

- - - Fix in PyTorch/Dynamo test infrastructure or upstream test port: make stream graph assertions backend-agnostic by normalizing stream IDs before assertExpectedInline, or update torch/_dynamo/variables/streams.py registration so graph-created stream numbering is deterministic across accelerator backends. - Then regenerate the XPU inline expectations in test/xpu/dynamo/test_streams_xpu.py only after the stream index contract is settled.
