Continue upstream-fix tracking under assignee.

## Root Cause

Not an XPU SYCL kernel correctness bug; a decomposition contract regression in upstream PyTorch. In
torch/_decomp/decompositions.py, adaptive max-pool decompositions exist for 2D/3D but return
NotImplemented for general non-evenly-divisible cases, and there's no adaptive_max_pool1d
decomposition, while the op schema returns (output, indices). Under test_decomp_xpu cross-ref the
decomposed output structure diverges from real output (tuple length mismatch), triggering assert
len(real_out)==len(decomp_out) across dtypes/dims. Hits many adaptive_max_pool* cases -> P1.

## Fix Approach

- Fix in upstream PyTorch decomposition layer: implement complete adaptive_max_pool{1,2,3}d decompositions always returning (Tensor, Tensor) incl non-evenly-divisible shapes, or guard partial decompositions so they don't emit NotImplemented in decomp paths.
- Add regression coverage in test/test_decomp.py for adaptive_max_pool1d/2d/3d (return_indices + uneven output_size).
- unskip XPU test_decomp_xpu entries after the upstream patch is merged/cherry-picked.
