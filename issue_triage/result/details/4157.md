## Root Cause

The cases exercise FP8 row-wise _scaled_mm via the v2 wrapper on XPU and expect an error for fp32
output-with-bias, but the XPU oneDNN-backed path does not enforce the same output-dtype guard as
CUDA's row-wise fallback. In aten/src/ATen/native/mkldnn/xpu/ScaledBlas.cpp, row-wise validation
checks scale/type/layout but has no out_dtype rejection for fp32, so no exception is raised and the
test fails with 'not raised'. An operator-side behavior mismatch, not a test-harness issue.

## Fix Approach

- Align XPU row-wise _scaled_mm v2 validation with expected semantics by adding an explicit dtype/bias guard in the XPU scaled-blas path (or centralize the check in shared _scaled_mm validation so CUDA/XPU are consistent).
- Update/confirm UT expectations for test_scaled_mm_row_wise_fp32_out_with_bias_errors_wrap_v2_* and run the targeted scaled-matmul XPU tests to verify the exception is raised.
