## Root Cause

Failing variants are in the mem-efficient SDPA dropout-mask path, where seq_len_q>1024 triggers the
guard that would launch _fill_mem_eff_dropout_mask with too many threads. On XPU this path is
intentionally runtime-skipped, so these are generated-but-skipped cases, not a functional
regression. The UT signal is a test/expectation alignment issue between upstream parametrization and
XPU backend limits. (Matches Phase 2.4 True-but-SKIPPED for this case.)

## Fix Approach

- Align upstream test expectations for XPU: mark these parameter combos as XPU-skip/xfail (or gate generation) when dropout is enabled and seq_len_q exceeds the thread-limit threshold.
- Keep coverage for supported shapes (<=1024) and document the backend constraint in the skip reason so ut_upstream treats them as expected skips.
