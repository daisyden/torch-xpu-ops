## Root Cause

The XPU nested-tensor OpInfo backward suite is missing the upstream XFail guard for nextafter
backward. Upstream test/test_nestedtensor.py marks nextafter backward as
nextafter_backward_not_implemented for (T, NT) samples, but
third_party/torch-xpu-ops/test/xpu/test_nestedtensor_xpu.py has no corresponding nextafter rule. The
new 2.13 path executes an unsupported nested-tensor backward route and raises RuntimeError on XPU
(Windows Arc B580).

## Fix Approach

- Sync the XPU mirrored nested-tensor skip/xfail list with upstream by adding the nextafter backward XFail rule in BACKWARD_SKIPS_AND_XFAILS (matching upstream op.full_name=='nextafter' with (T, NT) sample filter).
- This is test-expectation alignment, not a kernel fix.
- keep an issue link to remove the XFail once upstream nested-tensor nextafter backward support lands.
