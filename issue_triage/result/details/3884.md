## Root Cause

nn.Embedding forward routes through weight.index_select (aten/native/Embedding.cpp) ->
xpu::index_select_kernel (torch-xpu-ops/src/ATen/native/xpu/Indexing.cpp); advanced indexing ->
xpu::index_kernel (TensorAdvancedIndexing.cpp); all converge on the SYCL indexing backend in
sycl/Indexing.cpp + Indexing.h. Index bounds are enforced mainly by device-side SYCL_KERNEL_ASSERT
(or not checked in the index_select path) rather than host-side TORCH_CHECK, so out-of-range/invalid
index data becomes undefined device memory access; on some Intel iGPU configs this manifests as a
non-terminating kernel (hang) instead of a clean error.

## Fix Approach

- Add explicit host-side index range validation for all XPU indexing entry points before kernel launch (index_select_kernel, _index_kernel callers, embedding-forward), mirroring CPU/CUDA semantics ([-dim_size, dim_size-1]).
- Keep device asserts as debug-only backup.
- Add regression tests for index_select, advanced indexing, and nn.Embedding on XPU with valid + OOB indices to verify error behavior and prevent iGPU hangs.
