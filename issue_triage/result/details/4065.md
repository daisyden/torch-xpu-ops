## Root Cause

test_sdpa forces SDPBackend.FLASH_ATTENTION inside invoke_subgraph under torch.compile, so SDPA
cannot fall back. On XPU, backend selection fails with 'No available kernel' when flash isn't
selectable for the runtime config (Windows Arc B580), and the overrideable oneDNN path isn't a
viable fallback here because the test runs with autograd (requires_grad=True) which that path gates
out. Primarily a flash-SDPA backend selection/availability issue, not an invoke_subgraph functional
bug.

## Fix Approach

- Treat as a Flash-Attention/XPU backend gap: update the test to gate/skip when XPU flash is unavailable on the current platform+arch (or allow a non-flash fallback for this HOP compile coverage), and improve upstream XPU flash backend support/eligibility diagnostics on Windows Arc B580 so backend selection is explicit and stable under compile.
