## Root Cause

XPU distribution kernels compute Philox counter advancement from UNROLL in calc_execution_policy
(DistributionTemplates.h:40-52), but Philox state advances in 32-bit lanes and some paths (double
paths using rand_uniform2_double/rand_normal2_double) consume 4 lanes per call. Unlike CUDA
(aten/src/ATen/native/cuda/DistributionTemplates.h:35-60), XPU doesn't reserve a fixed max-per-call
offset, so the generator offset can be under-advanced at specific stream positions, causing
subsequence overlap/correlation and statistical bias.

## Fix Approach

- Make XPU offset accounting match CUDA: in calc_execution_policy, advance by a fixed Philox max-consumption unit (4 lanes) rather than UNROLL, or compute exact per-kernel lane consumption.
- Audit non-TensorIterator RNG kernels using hardcoded increments (Distributions.cpp constants 10/20/42) to reserve Philox space consistently.
- Add regression tests sweeping explicit generator offsets with statistical checks (uniform + vonmises, float + double).
