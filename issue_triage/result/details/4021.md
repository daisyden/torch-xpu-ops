## Root Cause

Both failures are thrown by standard distribution argument validation in torch.distributions, not
test assertions. In test_laplace_xpu, scale_1d from unconstrained torch.randn can be negative on XPU
(RNG sequence differences), triggering constraints.positive in Laplace.__init__. In
test_wishart_stable_with_precision_matrix_xpu, an RBF-derived matrix that should be
positive-definite is reported invalid by XPU constraints.positive_definite (via
torch.linalg.cholesky_ex), indicating backend numerical/op divergence.

## Fix Approach

- (1) Make the Laplace test param generation constraint-safe/device-stable by enforcing positive scale before construction.
- (2) investigate/fix XPU cholesky_ex/PD-check behavior on near-conditioned SPD inputs used by Wishart precision validation.
- Add targeted XPU regressions for both constructors (Laplace scale>0, Wishart precision_matrix=RBF) so validation passes consistently.
