## Root Cause

Running the entire test_torch_xpu.py file (TestTorch + TestTorchDeviceType together) triggers
'Segmentation fault from GPU ... drm_neo.cpp:269' during test_index_add* sequence, while individual
cases pass. Indicates GPU page fault / state corruption accumulated across many tests (likely stale
allocations or invalid pointer reuse interacting with driver/L0). Failure surfaces in
compute-runtime drm_neo.cpp, not in a specific kernel; root cause is most plausibly an XPU
cache/allocator or RNG state issue compounded by previous tests.

## Fix Approach

- - - - Bisect failing tests with pytest --collect-only to find the predecessor that corrupts state. - reproduce with ZE_DEBUG=4 / SYCL_PI_LEVEL_ZERO_USE_IMMEDIATE_COMMANDLISTS=0. - check XPU caching allocator and torch.xpu.empty_cache between tests. - File driver bug if confirmed L0 issue. - otherwise add per-test torch.xpu.synchronize/empty_cache and skip via allowlist until fixed.
