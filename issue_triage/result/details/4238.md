## Root Cause

`sync_module_states=True` in FSDP performs parameter/buffer synchronization through process-group
broadcast (`torch/distributed/fsdp/_init_utils.py:1110-1167`) which calls `_broadcast_coalesced`
(`torch/distributed/utils.py:318-328`). On XPU this flows through ProcessGroupXCCL broadcast
(`third_party/torch-xpu-ops/src/xccl/ProcessGroupXCCL.cpp:1436-1483`) into oneCCL broadcast wrappers
(`third_party/torch-xpu-ops/src/xccl/xccl.cpp:105-133`). The issue’s hang at FSDP wrap (before step
0) and workaround via oneCCL IPC/transport env vars indicate a communication-layer deadlock in
xccl/oneCCL IPC exchange behavior for the init broadcast path.

## Fix Approach

- Create a minimal distributed repro in CI that only performs FSDP construction with `sync_module_states=True` and records collective progress markers per rank.
- Then add diagnostics and timeout/error surfacing around broadcast work completion in ProcessGroupXCCL, and implement a guarded fallback transport/IPC mode when default exchange stalls on PCIe topologies.
