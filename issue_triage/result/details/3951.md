## Root Cause

XPU routes torch.linalg.lu_factor to oneMKL-backed LU but the implementation hard-requires
pivot=True and errors when pivot=False; CPU lu_factor without pivoting is also unavailable, so
pivot=False requests fail outright. Missing piece: XPU wiring for the no-pivot oneMKL path
(getrfnp/getrfnp_batch) and output handling. (This is the root cause behind NA issue #4180.)

## Fix Approach

- Implement a pivot=False branch in XPU linalg_lu_factor_ex_out/lu_factor_mkl calling oneMKL getrfnp (and getrfnp_batch for batched), filling LU/info correctly and returning a defined pivots tensor consistent with PyTorch no-pivot semantics.
- Keep pivot=True on getrf/getrf_batch unchanged.
- add XPU tests for pivot=False across single/batched matrices (real/complex, error/info).
