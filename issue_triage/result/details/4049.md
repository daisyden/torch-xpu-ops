## Root Cause

Legacy profiler JSON serialization in upstream PyTorch, not XPU kernel logic.
EventList.export_chrome_trace in torch/autograd/profiler_util.py manually concatenates JSON using
string formatting and writes evt.trace_name without JSON escaping. On Windows, backslashes in
names/paths become invalid escape sequences, so json.load raises JSONDecodeError: Invalid \escape in
test_event_list (mirrored in torch-xpu-ops).

## Fix Approach

- Fix upstream PyTorch by replacing manual string concatenation in EventList.export_chrome_trace with safe JSON encoding (build event dicts and json.dump, or at minimum json.dumps for string fields).
- Add a regression in test/profiler/test_profiler.py exercising a trace/event name containing Windows-style backslashes and verifying the exported trace parses.
- Cherry-pick/sync into release/2.13 and torch-xpu-ops.
