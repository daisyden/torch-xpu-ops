## Root Cause

The issue is a PyTorch 2.12 BMG performance-gap tracker where multiple Inductor benchmark rows have
speedup below 1. benchmarks/dynamo/common.py:1163-1178 defines speedup as eager median latency
divided by compiled median latency, and benchmarks/dynamo/check_perf_csv.py:21-44 treats rows below
the configured threshold as performance failures; the cited CSV rows therefore indicate compiled XPU
Inductor code is slower than eager for those models, not a torch-xpu-ops kernel crash.

## Fix Approach

- Profile the representative HuggingFace and TorchBench slowdowns on BMG, compare eager op time against generated Inductor kernels, and file/fix the dominant upstream Inductor issues such as fusion misses, excessive graph breaks, memory layout conversions, or Triton/XPU codegen choices.
- Track each model/dtype as a benchmark regression and require speedup >= 1 in the perf CSV before closing.
