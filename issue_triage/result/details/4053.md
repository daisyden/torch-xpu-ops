## Root Cause

Inductor training perf regression on Windows for TorchBench llama bf16 bs=2: PT2.13 13.88ms ->
16.715ms (~20.43%) while eager is healthy. The Triton label points to a Triton codegen/scheduling
change on Arc B580 in the 2.13 stack rather than model-level/eager behavior. Large delta +
hardware/OS specificity suggest a backend kernel-generation or launch-config regression in the
PT2.13 Inductor+Triton path.

## Fix Approach

- Bisect PyTorch/Triton between 2.12 and 2.13 on Windows Arc B580 using the exact llama training benchmark (bf16, bs=2) to find the first bad change.
- capture per-kernel timings and generated Triton code to isolate regressed kernels.
- Compare launch params/tiling/fusion/memory-access vs 2.12-good.
- patch Triton lowering/autotune heuristics (or pin known-good configs) for this workload on Intel XPU Windows.
- Add a Windows XPU llama-training perf guardrail.
