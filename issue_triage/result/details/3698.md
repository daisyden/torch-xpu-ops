## Root Cause

The meta cross-reference harness first runs the real operator at
third_party/torch-xpu-ops/test/xpu/test_meta_xpu.py:629 and converts any real-op exception into
"Original OpInfo is broken" at test_meta_xpu.py:631; test_meta_outplace drives all OpInfo samples at
test_meta_xpu.py:1570 and calls the op at test_meta_xpu.py:1591. The failing operator is
aten::_flash_attention_forward, but the fallback registration only lists
_efficient_attention_forward at
third_party/torch-xpu-ops/src/ATen/native/xpu/XPUFallback.template:232 and omits
_flash_attention_forward, even though the dependency lookup lists _flash_attention_forward as an
attention CPU fallback operator. The native flash API exists in
src/ATen/native/transformers/xpu/flash_attn/flash_api.cpp:24, but without the fallback/native
registration available for this build the dispatcher reports the XPU operator as not implemented.

## Fix Approach

- - - Register aten::_flash_attention_forward for XPU, either by adding a proper native schema/dispatch entry to yaml/native/native_functions.yaml for the implementation in src/ATen/native/transformers/xpu/flash_attn/flash_api.cpp, or by adding it to the CPU fallback list in src/ATen/native/xpu/XPUFallback.template until native coverage is ready. - Keep test/xpu/test_meta_xpu.py only as validation. - do not mask the failure in the meta test.
