## Root Cause

torch.svd_lowrank and torch.lobpcg are iterative linalg routines repeatedly launching GEMM-heavy
steps (matmul/QR/SVD, Rayleigh-Ritz updates). On BMG XPU in release/2.13 these tests time out as
hangs (not numerical mismatches), pointing to backend kernel completion/progress failure rather than
test logic. Regression scope (2.13 vs 2.12) + operator mix implicate oneMKL-backed linalg/GEMM on
SYCL for these iterative paths.

## Fix Approach

- Create minimal repros on BMG (svd_lowrank with niter loop, lobpcg with bounded niter), capture oneMKL/SYCL verbose traces, bisect runtime/library changes 2.12->2.13.
- Add a temporary skip for affected BMG cases in test_linalg_xpu/BMG skip lists to unblock CI, then land a backend fix forcing a safe linalg code path (or synchronization workaround) for the iterative GEMM sequence.
- validate with regression tests + timeout guards.
