## Root Cause

The failing XPU test compiles nested-tensor op samples with torch.compile(...,
backend="aot_eager_decomp_partition") and then runs autograd.grad on the compiled outputs at
third_party/torch-xpu-ops/test/xpu/test_nestedtensor_xpu.py:8952 and
third_party/torch-xpu-ops/test/xpu/test_nestedtensor_xpu.py:8975. The traceback bottoms out in
PyTorch symbolic shape arithmetic: ConstantIntNode.add delegates to other.add at
torch/fx/experimental/_constant_symnode.py:44, but NestedIntNode only implements mul/comparisons and
has no add method at torch/nested/_internal/nested_int.py:80. This is a PyTorch
NestedInt/FakeTensor/AOTAutograd gap exposed by XPU nested tensor compile tests, not an XPU kernel
failure.

## Fix Approach

- Fix PyTorch nested symbolic integer support by adding the missing NestedIntNode arithmetic needed by ConstantIntNode/NestedInt interactions, or avoid producing that unsupported expression in AOTAutograd fake/meta tracing.
- Add a focused nested tensor torch.compile backward test for nextafter broadcasting that exercises constant + NestedInt shape arithmetic.
