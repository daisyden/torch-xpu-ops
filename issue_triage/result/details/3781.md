## Root Cause

XPU convolution is implemented in PyTorch's oneDNN override, where _convolution_out normalizes
tensor layout and makes input/weight contiguous before invoking onednn::convolution at
aten/src/ATen/native/mkldnn/xpu/Conv.cpp:324-331 and 394-403. The operator registry also maps
conv2d/conv3d to the oneDNN path at
third_party/torch-xpu-ops/.opencode/skills/bug_scrub/prepare_data/pytorch_xpu_backend_analysis/xpu_supported_operators_complete_list.md:126-132
and 843-844. The reported OOB gap is quantified (+0.0101 geomean R delta on B580, +0.0062 on G31, 48
models, densenet121 18.67x T2), pointing to oneDNN convolution primitive selection or
layout-conversion overhead for B580/G31 fp16 inference.

## Fix Approach

- Profile the worst convolution shapes with oneDNN verbose to identify selected primitives, memory formats, reorder time, and whether make_contiguous_and_aligned dominates.
- Add targeted conv microbenchmarks for the densenet/detectron/timm shapes, tune layout selection or cache/reuse reordered weights in the PyTorch XPU wrapper where possible, and file reduced oneDNN cases for pathological primitive choices.
