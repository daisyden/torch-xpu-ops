## Root Cause

Triton-generated persistent reduction used by Inductor combo kernels combines fp32 partial sums via
tl.atomic_add(sem='relaxed'). FP addition is non-associative, so relaxed atomic ordering allows
different interleavings across runs/devices, producing observable accuracy divergence. A
codegen-level numerical-ordering issue, not an isolated model/test bug.

## Fix Approach

- Update Triton reduction codegen for fp32 persistent reductions to avoid relaxed atomic accumulation in accuracy-sensitive paths (deterministic tree/block reduction with a single ordered final write, or stronger atomic semantics where required).
- Enable a regression in test/inductor/test_combo_kernels.py::ComboKernelTests::test_combo_kernel_no_bench_persistent_reduction to lock behavior.
