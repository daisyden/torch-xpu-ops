## Root Cause

XPU profiler event emission differs on Windows: Kineto captures low-level UR launch records
(urEnqueueKernelLaunch) where the test expects a CUDA-like aten event progression. The FX
stack-trace augmentation is present, but the assertion is brittle to backend-specific event
naming/count/order for XPU addmm kernels, so the expected 'aten::relu node=relu' line is reached too
early in the golden-trace comparison and the test fails.

## Fix Approach

- Make the XPU test expectation backend-normalized instead of strict CUDA-style ordering: pre-filter UR/ZE bookkeeping events, canonicalize UR launch-name variants, and assert the aten->node stack-trace attribution invariants (incl relu mapping) rather than exact line-by-line sequence.
- Port the normalization logic from newer test_fx_xpu.py into release/2.13 and rebaseline the Windows XPU expected trace.
