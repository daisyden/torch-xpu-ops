## Root Cause

test_bf16_stochastic_round fails on PVC1100 with one element exceeding atol=3e-5 (abs diff 0.00238).
The _fp32_to_bf16_sr stochastic-rounding path relies on bitwise/integer ops and bf16 truncation; the
small numeric drift suggests RNG/bit-manipulation lowering on XPU eager path differs slightly vs
reference. Test passes on BMG per @arlesniak but reproduces on PVC, so it is a PVC-specific eager
numerics gap rather than a TorchAO bug.

## Fix Approach

- - - - Reproduce on PVC, isolate which op in _fp32_to_bf16_sr (bitwise_and/right_shift/add then bitcast to bf16) produces drift. - verify XPU integer add with carry for the random-bias path matches CPU/CUDA. - If acceptable, relax tolerance upstream in torchao or skip on PVC. - otherwise fix the XPU bitwise/shift kernel rounding.
