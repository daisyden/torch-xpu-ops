## Root Cause

The failing XPU test is inherited from upstream
test/distributions/test_distributions.py::test_relaxed_one_hot_categorical_2d; the distribution impl
(torch/distributions/relaxed_categorical.py) is upstream with no torch-xpu-ops override. It's a
gradcheck on RelaxedOneHotCategorical.log_prob near an instability boundary (temperature=0.25) where
finite-difference Jacobians are highly sensitive. On XPU, small numerical error in the
elementwise/logsumexp path amplifies enough to trigger GradcheckError - a precision-sensitive
backend behavior, not a distribution-logic regression.

## Fix Approach

- Backend numerical-precision triage: reproduce with fixed seed and compare CPU vs XPU Jacobians for the same sample.
- bisect the mismatch across log/exp/logsumexp in double precision on XPU.
- If primitive-op parity is off, route to XPU kernel precision owners.
- if parity is acceptable, adjust the XPU test expectation (tolerance/xfail at boundary temperature) while keeping stronger temperatures covered.
