## Root Cause

The issue compares the same PT2E/Inductor vision benchmark between driver 25.40 and 26.19 and shows
large Top1 accuracy collapses, so the primary change is below the PyTorch/torch-xpu-ops source
layer. The PT2E quantized convolution path is lowered through Inductor to QConvPointWisePT2E at
torch/_inductor/mkldnn_lowerings.py:617 and then into oneDNN-backed XPU qconv at
aten/src/ATen/native/mkldnn/xpu/qconv.cpp:92; regular XPU convolution also calls oneDNN at
aten/src/ATen/native/mkldnn/xpu/Conv.cpp:351. Because both fp32 and int8 model families regress only
with the new driver, the likely root cause is a driver/IGC/runtime regression in the oneDNN XPU
kernels used by Inductor PT2E execution.

## Fix Approach

- - Minimize one or two affected models to the first wrong conv/qconv/linear output under driver 26.19, then file the reduced kernel and descriptor details against the driver/IGC stack. - Use driver 25.40 as the known-good workaround, and add a CI guard or driver-version xfail only if a driver fix cannot land quickly.
