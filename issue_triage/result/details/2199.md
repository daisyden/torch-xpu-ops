## Root Cause

The spill warning maps to the XPU reduction template stack: ReduceArgMinKernel.cpp dispatches
ArgMinOps into gpu_reduce_kernel, instantiating the generic ReduceKernel/ReduceOp path in Reduce.h
for SIMD32. The same framework is reused by ReduceNormKernel.cpp for norm variants, so complex
per-thread state and specialization depth inflate live registers and trigger spills (256 regs, ~94
spilled) across multiple reduction kernels.

## Fix Approach

- Refactor the reduction hot path to lower register pressure for SIMD32: simplify ArgMin/Norm operator state, reduce temporary/live value lifetimes in the Reduce.h kernel loop, split heavy specializations into lighter kernels for argmin + selected norm modes.
- Validate with SYCL compiler register reports + perf microbenchmarks.
- keep the lower-spill variant as default.
