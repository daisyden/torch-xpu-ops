## Root Cause

The test asserts an exact RuntimeError message for user-specified stream input mutation, but on the
XPU/Windows dynamo compile path the failure is surfaced as a wrapped backend/compiler error instead
of that exact top-level string. The underlying unsupported behavior (epilogue mutation with user
stream metadata) is the same; exception wrapping/formatting changes the observable message and
breaks strict regex matching. A message-surface mismatch, not a stream-semantics regression.

## Fix Approach

- In the XPU streams test, stop matching only one exact top-level message.
- assert the semantic failure more robustly (accept BackendCompilerFailed-wrapped errors or inspect the exception cause text for 'Mutations on inputs with user-specified streams').
- Align with upstream dynamo test behavior and backport the assertion update to release/2.13 if needed.
