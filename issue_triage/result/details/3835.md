## Root Cause

On XPU, SDPA backend selection in aten/src/ATen/native/mkldnn/xpu/Attention.cpp prioritizes
'overrideable' (oneDNN) ahead of flash attention. The failing repro test_sdpa_dynamic_shapes uses
bf16+causal SDPA under Dynamo dynamic shapes, routing through the oneDNN overrideable path which
does not match expected eager reference numerics in this config. This is an XPU SDPA
backend-selection/accuracy issue in the oneDNN path, not a pure Inductor failure.

## Fix Approach

- Adjust XPU SDPA backend gating/priority so this dynamic-shape causal bf16 case avoids the inaccurate overrideable path: prioritize flash over overrideable for this case, or make can_use_overrideable_attention reject unsupported dynamic/causal combos and fall back to flash/math.
- Add a regression asserting eager vs torch.compile(dynamic=True) parity for this shape pattern in test/dynamo/test_repros.py.
