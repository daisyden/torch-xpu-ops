## Root Cause

The failing dynamo/test_streams_xpu.py tests compute a rate/ratio using elapsed stream/event time;
on XPU the measured elapsed time can be reported as 0 under current driver timing
granularity/synchronization behavior. That zero duration propagates into Python arithmetic and
triggers ZeroDivisionError (test_record_stream_problem_basic/interleaved). A runtime stream-timing
edge case, not a Dynamo compile correctness bug.

## Fix Approach

- Harden stream-timing/record_stream tests and helper math to treat non-positive elapsed time as a valid edge case: synchronize before reading timing, guard the denominator with epsilon or an explicit zero-check, retry/re-measure when elapsed==0.
- Keep assertions on record_stream ordering/liveness semantics rather than strict non-zero micro-timing.
- Coordinate with driver owners on timer-resolution behavior.
