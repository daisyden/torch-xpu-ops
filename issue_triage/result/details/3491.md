## Root Cause

The performance regression is isolated to PT2E INT8 Inductor quantization on XPU for resnext50_32x4d
while FP32 is stable, pointing at the shared quantized convolution lowering rather than the
benchmark harness. That lowering supports XPU through SUPPORTED_MKLDNN_DEVICES = ("cpu", "xpu") in
torch/_inductor/utils.py:4118, creates oneDNN qconv extern calls with kernel name
aoti_torch_xpu__qconv_pointwise_tensor in torch/_inductor/mkldnn_ir.py:581-607, and builds the
QConvPointWisePT2E inputs/constant args through _prepare_convolution_fusion_create at lines 617-680.
The same path materializes int32 weight zero points in torch/_inductor/mkldnn_lowerings.py:756-764
and benchmarks GPU extern choices via TensorMeta in torch/_inductor/select_algorithm.py:3278-3286,
so a layout/fusion/autotune change in the oneDNN-backed qconv path can slow grouped INT8 convolution
without affecting FP32.

## Fix Approach

- - - Bisect PyTorch 2.11 to 2.12 changes in the PT2E mkldnn qconv path, then inspect generated Inductor code and oneDNN graph primitive selection for grouped convolutions in resnext50_32x4d. - Fix the shared lowering/autotune path in torch/_inductor/mkldnn_ir.py, mkldnn_lowerings.py, or select_algorithm.py so XPU preserves the intended channels-last/grouped-conv fusion and selects the fast oneDNN qconv primitive.
