## Root Cause

Test-environment/build-integrity problem, not an operator regression: cases fail importing/loading a
torch shared library from a temporary build path under /tmp/xpu-tool/.../torch/build/lib. Indicates
an incomplete/mismatched torch build/install or stale loader paths (Python imports one torch while
the dynamic linker resolves incompatible/missing .so from another location). Broad impact across
converter/export tests supports a single shared environment breakage.

## Fix Approach

- Recreate a clean torch runtime: remove stale build artifacts, rebuild+install torch in one environment, ensure tests resolve libraries from that install only (sanitize PYTHONPATH/LD_LIBRARY_PATH, avoid /tmp build-lib leakage).
- Add a CI preflight that imports torch and runs ldd/loader validation on key torch .so before UTs, failing fast on unresolved/mixed-path dependencies.
