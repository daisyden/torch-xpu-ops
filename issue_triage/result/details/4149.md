## Root Cause

Feature gap, not a regression: triangular_solve.X is defined upstream but lacks full XPU backend
registration/implementation for the dense path. The XPU dispatch entry and kernel are
missing/incomplete, so calls cannot execute natively on XPU and coverage (upper/lower, transpose,
unitriangular, structured out semantics) is absent.

## Fix Approach

- Add XPU dispatch for triangular_solve.X in native_functions.yaml/codegen wiring, implement the XPU out kernel via oneMKL BLAS trsm (and batched trsm where appropriate) with correct upper/transpose/unitriangular mapping and output alias/shape checks, then enable/extend XPU tests for dense (and SparseCSR) cases plus perf guardrails vs CPU baseline.
