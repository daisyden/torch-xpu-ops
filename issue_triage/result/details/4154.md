## Root Cause

linalg_lstsq.out is not registered for the XPU dispatch key, so XPU tensors can't take the intended
backend path for least-squares solve, and there's no XPU kernel wired to oneMKL GELS-style routines.
An operator-implementation gap despite existing API/schema in PyTorch.

## Fix Approach

- Add XPU registration for linalg_lstsq.out in the backend dispatch table and implement the XPU kernel using oneMKL LAPACK GELS (workspace/query handling, batched/strided cases, dtype constraints).
- Validate parity with CPU/CUDA for outputs/residuals/rank/singular values.
- add XPU tests for real/complex, over/underdetermined systems, and error handling.
