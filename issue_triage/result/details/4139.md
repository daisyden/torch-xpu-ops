## Root Cause

Release regression on LNL 2.12->2.13 in XPU eager OpInfo paths, not a baseline issue: tests
previously passed and now fail with NaN mismatches (incl complex32 reference checks), clustering
around chunk_cat and split_with_sizes_copy out/reference variants. Linux repro also shows UR
out-of-resources for related sample inputs, indicating unstable XPU kernel/runtime behavior rather
than tolerance-only drift. Likely fault domain: the XPU SYCL kernel path (and its launch/resource
handling) for these ops on LNL.

## Fix Approach

- Reproduce with the OpInfo sample indices on LNL Windows + Linux, isolate aten::chunk_cat and split_with_sizes_copy XPU execution against CPU and 2.12 baselines to find where NaNs/out-of-resources first appear.
- Bisect 2.12->2.13 across torch-xpu-ops XPU kernels + relevant upstream XPU dispatch/copy plumbing.
- patch the SYCL path for safe shape handling (edge split sizes) and stable complex-half compute/casting.
- Add regressions for the failing sample inputs (out + complex_half_reference_testing) on LNL.
