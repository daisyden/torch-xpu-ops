## Root Cause

The reported failing assertion compares GroupNorm output for channels-last input against a
contiguous reference in a CPU-only test path
(third_party/torch-xpu-ops/test/xpu/test_nn_xpu.py:11681,
third_party/torch-xpu-ops/test/xpu/test_nn_xpu.py:11721), and the same upstream PyTorch test has the
same comparison logic (test/test_nn.py:9425, test/test_nn.py:9454). torch-xpu-ops only registers XPU
dispatch stubs for GroupNorm (third_party/torch-xpu-ops/src/ATen/native/xpu/GroupNorm.cpp:20,
third_party/torch-xpu-ops/src/ATen/native/xpu/GroupNorm.cpp:23), but issue comments note the XPU
failures are comparisons against CPU and diagnose it as a CPU regression. The root problem is
therefore an upstream PyTorch normalization accuracy/tolerance or CPU implementation issue exposed
by the ported test, not an XPU kernel defect.

## Fix Approach

- Open or link an upstream PyTorch issue with the CPU-only GroupNorm/LayerNorm reproducer on Windows, verify whether the CPU channels-last reference changed, and adjust upstream tolerances or CPU normalization behavior there.
