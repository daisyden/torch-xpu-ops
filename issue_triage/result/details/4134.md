## Root Cause

XPU foreach fast-path regression, not a generic autograd test issue. The XPU foreach unary inplace
path (_foreach_tan_) diverges from CUDA (notably a missing inplace version-counter bump), corrupting
autodiff bookkeeping and surfacing as a complex128 gradcheck Jacobian mismatch. For _foreach_max,
the XPU SYCL reduction diverges from CUDA reduction semantics/robustness, the likely source of the
float64 Jacobian mismatch seen only on LNL Windows.

## Fix Approach

- Align XPU foreach kernels with CUDA: add increment_version(tensors) in XPU foreach unary inplace kernels, and update XPU foreach max reduction to match CUDA reduction semantics (incl NaN/edge handling and reduction parity).
- Add regression for test_autodiff on _foreach_max (outplace, float64) and _foreach_tan_ (inplace, complex128) on XPU/Windows.
- interim mitigation: route these dtype/op combos to slow path on LNL until kernel parity is verified.
