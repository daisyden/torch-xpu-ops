## Root Cause

Cases generated by test/test_foreach.py::TestForeach.test_autodiff across foreach
unary/binary/pointwise families; in 2.13 these samples heavily exercise empty/interspersed-empty
tensor paths. The thrown 'max(): Expected reduction dim ...' matches core reduction behavior for
max() on empty tensors without an explicit dim, so the failure is in shared autodiff/gradcheck
reduction handling (or foreach autograd formula interaction), not a single XPU foreach kernel.
Explains the broad 142-UT blast radius and 2.13-vs-2.12 regression.

## Fix Approach

- Treat as an upstream PyTorch regression: bisect 2.12->2.13 around foreach autodiff sample generation and gradcheck/autograd reductions on empty tensors, then patch the foreach autodiff path to avoid no-dim max() on empty intermediates (guard empty tensors in foreach autodiff input generation, or use a dim-safe/empty-safe reduction in the gradcheck/autograd path).
- Add a focused regression for foreach autodiff with interspersed empty tensors on XPU.
