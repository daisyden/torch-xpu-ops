## Root Cause

This is CI triage automation, not an operator failure: .github/scripts/ut_result_check.sh has a
hard-coded ignore list for random/pass detection at lines 40-49 and its skipped-UT logic only
suppresses NEW PASSING TESTS when an ignored pattern appears at lines 185-194. The normal suite path
separately detects Passing Known Issues at lines 235-237 and calls mark_passed_issue at lines
104-107, so issues tagged as random can be hidden from closure/new-pass handling without preserving
per-run pass/fail history.

## Fix Approach

- - - Update .github/scripts/ut_result_check.sh so random-labeled issues are excluded only from auto-close/new-pass gating, but still produce a scheduled-run GitHub comment summarizing whether each random issue's tracked cases passed or failed. - Reuse the existing passed/failed log comparison and gh issue comment machinery rather than changing operator code.
