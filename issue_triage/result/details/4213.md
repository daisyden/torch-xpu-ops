## Root Cause

Parity failures come from exception asymmetry in foreach-copy testing: when foreach path throws, the
harness requires reference `Tensor.copy_` to throw the same type (`test/test_foreach.py:229-263`).
XPU foreach copy fastpath dispatch only covers ALL_TYPES + complex + {Half,BFloat16,Bool}
(`third_party/torch-xpu-ops/src/ATen/native/xpu/sycl/ForeachCopyKernels.cpp:123-136`), so float8
dtypes are not supported on that path. Because routing prefers fastpath before slow fallback
(`third_party/torch-xpu-ops/src/ATen/native/xpu/ForeachOpList.cpp:188-190`), float8 cases can raise
backend NotImplemented in foreach while reference copy path does not, yielding the observed
`NotImplementedError not raised` parity failures.

## Fix Approach

- Either (A) implement float8 support in XPU foreach-copy kernel dispatch, or (B) explicitly exclude/skip float8 for `_foreach_copy` in XPU OpInfo until kernel support exists.
- Validate by re-running all listed foreach float8 parity cases and confirming no exception-mismatch path remains.
