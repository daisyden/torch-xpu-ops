## Root Cause

The async-TP fusion in torch/_inductor/fx_passes/micro_pipeline_tp.py is gated by
torch.distributed.is_nccl_available() and is_symm_mem_enabled_for_group(), so on XPU the
all_gather+matmul pattern is not rewritten into fused_all_gather_matmul. Also
torch/distributed/_symmetric_memory/__init__.py registers fused_all_gather_matmul for Meta and CUDA
but not XPU, so even with pattern matching there's no XPU backend op path -> the test assertion for
'fused_all_gather_matmul' fails.

## Fix Approach

- Upstream PyTorch should make micro-pipeline TP fusion backend-capability-based (not NCCL-only), add/enable XPU symmetric-memory support for the target process group, and register an XPU implementation (or valid fallback dispatch) for symm_mem::fused_all_gather_matmul.
- In torch-xpu-ops, keep the test skipped/xfail until those upstream async-TP + symm_mem pieces land, then unskip with a targeted regression for XPU fusion pattern emission.
