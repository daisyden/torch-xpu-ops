## Root Cause

Backend runtime regression in XPU AMP grad scaling, specifically the SYCL path for
_amp_foreach_non_finite_check_and_unscale_ used by GradScaler.step() during gradient accumulation.
Failure only on LNL Windows in 2.13 (passing on LNL 2.12 and BMG 2.13) -> a platform-specific
behavior change in that kernel/runtime interaction, not test logic. Mismatched model parameters
indicate unscale/step semantics diverged from the non-AMP control path, causing optimizer-state
drift.

## Fix Approach

- Reproduce test_grad_scaling_accumulation_xpu and instrument per-step grads/inv_scale/found_inf for control vs scaling on LNL Windows, then bisect fast-route vs fallback in third_party/torch-xpu-ops/src/ATen/native/xpu/sycl/AmpKernels.cpp.
- Align the SYCL foreach unscale path with CUDA semantics (safe found_inf update, strict queue/ordering for inv_scale->unscale->update).
- add an XPU regression asserting accumulated-step parity for AMP scaling on Windows LNL.
