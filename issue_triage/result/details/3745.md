## Root Cause

XPU _scaled_mm_v2 only dispatches tensorwise_tensorwise and rowwise_rowwise recipes in
aten/src/ATen/native/mkldnn/xpu/ScaledBlas.cpp:367, so DeepSeek blockwise recipes fall through to
generic oneDNN/XPU shape validation or no ValueError instead of the test's expected
unsupported-configuration error. The XPU override in test/xpu/test_scaled_matmul_cuda_xpu.py:121
explicitly expects ValueError('Invalid scaling configuration') for six DeepSeek blockwise cases, but
the current validation at aten/src/ATen/native/mkldnn/xpu/ScaledBlas.cpp:659 runs too late and
reports scale_a/scale_b shape details or accepts some unsupported inputs.

## Fix Approach

- Add explicit early validation in _scaled_mm_xpu_v2_out for unsupported DeepSeek BlockWise1x128/BlockWise128x128 combinations and raise the stable 'Invalid scaling configuration' ValueError before oneDNN scaled_matmul shape checks.
- Keep tensorwise/rowwise behavior unchanged and update the XPU scaled-matmul tests to assert all six blockwise unsupported cases raise the same XPU-facing error.
