## Root Cause

XPU oneMKL out-variants are wrappers that run the non-out kernel into a temporary then resize+copy_
into out, adding an extra allocation + device copy. _fft_c2c_mkl_out does `auto
result=_fft_c2c_mkl(...)` then `out.copy_(result)`
(torch-xpu-ops/src/ATen/native/xpu/mkl/SpectralOps.cpp:392-395); same pattern in _fft_c2r_mkl_out
(:472-475) and _fft_r2c_mkl_out (:561-565), on the main oneMKL FFT out path
(xpu/SpectralOps.cpp:47,82-83,118).

## Fix Approach

- Refactor the three _fft_*_mkl_out to compute directly into out: resize/validate out up front, route _exec_fft to write to out via destination-accepting helpers, keep temporaries only for unavoidable multi-dim staging, eliminate the final result-to-out copy.
- Add perf-regression coverage for out-variants confirming reduced copy overhead and numerical parity.
