## Root Cause

The benchmark harness demotes fp64 reference failures to cosine mode instead of treating them as a
run failure: benchmarks/dynamo/common.py:2274 catches any exception from the fp64 run, logs it, sets
self.args.cosine=True at benchmarks/dynamo/common.py:2280, and continues with fp64_outputs=None.
Later accuracy starts from accuracy_status="pass" at benchmarks/dynamo/common.py:2292 and compares
eager-vs-compiled outputs, so the issue's SAM XPU OOM during fp64 reference generation can still end
in a printed pass when subsequent checks do not fail.

## Fix Approach

- - - Fix pytorch/benchmarks/dynamo/common.py so device OOM while generating the golden reference records an OOM/fail status instead of falling back to cosine. - use torch.OutOfMemoryError or backend-neutral OOM handling rather than CUDA-only checks, then add a benchmark-runner regression test for fp64 reference OOM status propagation.
