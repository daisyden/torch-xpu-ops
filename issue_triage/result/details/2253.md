## action_reason

* Authoritative duplicate disposition: 'duplicate' label + MEMBER comment (daisyden) declaring duplicated with #2289 -> close-as-not-target short-circuits PR tracking. (Open upstream candidate pytorch/pytorch#176688 enables test_dtypes/OpInfo dtype alignment, CI failing 2026-05-22 stale, but duplicate disposition takes precedence.) #3188 docs, #3385/#2303 test-decorator/python_ref_db wrong_symptom.

## Root Cause

test_dtypes_* failures on
addmm/addmv/baddbmm/mv/conv{1,2,3}d/conv_transpose1d/histogram(dd)/einsum/mm and
test_python_ref__refs_true_divide_xpu_complex32. The supported_dtypes returned by XPU dispatch
(registered via third_party/torch-xpu-ops/yaml/native/native_functions.yaml and OpInfo entries in
pytorch/torch/testing/_internal/common_methods_invocations.py) do not match the CUDA-declared dtypes
that test_dtypes asserts against. Labelled `duplicate, ut_upstream` — the discrepancy lives in
upstream OpInfo dtype declarations vs XPU registration.

## Fix Approach

- - - - Either expand XPU op registrations to cover the same dtype set as CUDA (e.g. addmm/addmv/baddbmm complex32, conv*d half/bfloat16 paths) or update OpInfo dtypesIfXPU in upstream torch/testing/_internal/common_methods_invocations.py so test_dtypes reflects actual XPU support. - Drop entries already crossed-out. - coordinate with the duplicate tracker.
