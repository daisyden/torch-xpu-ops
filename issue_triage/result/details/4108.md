## Root Cause

FakeTensor metadata cross-check on aten._fft_c2r.default where expected and concrete strides diverge
on XPU. In the XPU path (third_party/torch-xpu-ops/src/ATen/native/xpu/mkl/SpectralOps.cpp),
_fft_c2r_mkl forces input = input.clone(MemoryFormat::Contiguous) before _exec_fft, changing the
stride-driven permutation/restriding. The meta kernel (torch/_meta_registrations.py::meta_fft_c2r)
models upstream MKL-style _exec_fft layout without that XPU-specific contiguity normalization, so
FakeTensor predicts different output strides.

## Fix Approach

- Align XPU _fft_c2r_mkl layout semantics with meta/upstream by removing or narrowing the unconditional contiguous clone and preserving stride-informed layout through _exec_fft (or explicitly reproducing the same post-FFT as_strided contract).
- If contiguity is required for oneMKL correctness, add a deterministic restride after execution to match meta's expected stride pattern.
- extend XPU fake_crossref FFT tests (hfft2/hfftn/irfft2/irfftn, amp + no-amp).
