## Root Cause

The regression is in CPU Inductor OpenMP loop-collapsing: the test requires generated code to
contain '#pragma omp for collapse(2)' (test/inductor/test_cpu_repro.py:6656-6666), but codegen only
emits collapse when loop parallel depth is >1 (torch/_inductor/codegen/cpp.py:6240-6243). This means
the scheduler/codegen path for the transpose+contiguous kernel is now producing a non-collapsed loop
nest for this case, so the pragma check fails even though numerical output still matches
(test/inductor/test_cpu_repro.py:6664-6666). Because this behavior is implemented in upstream
Inductor codegen logic (not torch-xpu-ops kernels), ownership is upstream-pytorch.

## Fix Approach

- Instrument the lowered loop nest for this repro to confirm why parallel depth dropped to 1, then adjust the loop-collapsing heuristic/scheduling so the 2D transpose kernel regains collapse(2) emission.
- Add a focused regression assertion around the scheduling decision (not just the final string check) to prevent future silent heuristic drift.
