## Root Cause

These failures are produced by upstream compiled-vs-reference tolerance checks in flex/paged
attention tests, where `_check_equal` fails if compiled error exceeds `ref_error * fudge_factor`
(`test/inductor/test_flex_attention.py:7914-7929`) and emits the same message pattern noted in the
issue (`...:619-622`). The affected test methods are upstream inductor/flex-attention tests
(`test_builtin_score_mods_automatic_dynamic` at `...:1540-1543`, `test_paged_builtin_score_mods` at
`...:8227-8230`) and are enabled for XPU via generic instantiation (`...:9501-9510`). This points to
an upstream torch.compile/flex-attention numerical parity problem in compiled execution, not a
torch-xpu-ops internal-only dispatch bug.

## Fix Approach

- Reproduce a reduced subset of failing score_mod/BLOCK/head_dim cases and compare eager vs compiled intermediate outputs (including paged block conversion) to isolate the first divergence site.
- Then patch upstream flex-attention/inductor lowering or kernel option selection for those shapes/dtypes, and add targeted regression tests for both standard and paged paths using the failing parameter combinations.
