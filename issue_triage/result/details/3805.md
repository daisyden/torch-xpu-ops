## Root Cause

The failing compare_cpu frexp cases are generated through the XPU TestCommon instantiation at
third_party/torch-xpu-ops/test/xpu/test_ops_xpu.py:30 and compare CPU vs XPU with 1e-3 tolerance in
test/test_ops.py:519. XPU frexp dispatch is registered at
third_party/torch-xpu-ops/src/ATen/native/xpu/UnaryOps.cpp:91 and implemented via FrexpFunctor using
std::frexp in third_party/torch-xpu-ops/src/ATen/native/xpu/sycl/UnaryKernels.cpp:273, which returns
mantissa/exponent values that differ from CPU on Windows for all four floating dtypes. The Windows
MTL skip list already records the affected frexp dtype cases at
third_party/torch-xpu-ops/test/xpu/extended/skip_list_win_mtl.py:13.

## Fix Approach

- Reproduce the Windows XPU frexp mantissa/exponent mismatch on representative finite, subnormal, zero, inf, and nan inputs, then adjust UnaryKernels.cpp to match CPU frexp semantics or add narrowly justified Windows XPU tolerances only if the backend intrinsic cannot be made bit-compatible.
