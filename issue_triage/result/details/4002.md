## Root Cause

Regression in the PT2E INT8 export/quantization path (owned under TorchAO). On 2.13 RC the flow
resolves an aten.transpose overload by name using an invalid/unsupported overload token (likely the
Dimname variant), raising AttributeError at runtime during PT2E quant/export preparation, so models
fail before accuracy comparison - a release-blocking INT8 regression vs 2.12.

## Fix Approach

- Patch upstream PyTorch PT2E/export operator resolution to use schema-validated aten.transpose overload selection (or overload-agnostic lookup) instead of brittle string-based names.
- ensure the quantized graph emits the correct transpose variant for INT8.
- Add a PT2E INT8 regression exercising transpose in the export/quant pipeline on the 2.13 branch and backport.
