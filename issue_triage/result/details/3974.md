## Root Cause

fp16 accuracy divergence isolated to depthwise convolution with channels_last layout
(test_depthwise_conv_64bit_indexing) on XPU. Depthwise conv on this path is oneDNN-backed; fp16
accumulation/order differences in the channels_last kernel produce error beyond tolerance. Reference
behavior is consistent outside this config, pointing to backend precision behavior, not a broad API
mismatch.

## Fix Approach

- Reproduce/isolate the oneDNN depthwise+channels_last fp16 path with a minimal script matching test shapes/indexing.
- compare against fp32 accumulation and contiguous layout.
- Tighten backend selection/kernel attributes for this case (force safer accumulation/compute mode or fallback) when error exceeds tolerance.
- add an XPU regression around depthwise channels_last fp16 accuracy.
