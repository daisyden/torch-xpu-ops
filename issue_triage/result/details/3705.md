## Root Cause

The Intel Triton XPU backend's runtime JIT-compiles a SPIR-V utility module
(triton/backends/intel/driver.py:350 compile_module_from_src on driver.c, invoked from
XPUUtils.__init__ at driver.py:313 and _build at runtime/build.py:153) using MSVC on Windows. The
generated main.cpp requires C++20 features (designated initializers at line 620, and lambda-capture
of constexpr index variables like EXTRACTOR_*_INDEX at lines 959-997), but the Triton Windows build
invokes cl.exe without /std:c++20, so MSVC rejects it with C7555/C7556/C3480/C3260 errors. A
secondary manifestation after upgrading Triton (3.7.2+git07087654) is that generated SPIR-V uses the
SPV_INTEL_predicated_io extension which is unrecognized by older Intel Arc Windows GPU drivers
(<8801), causing 'InvalidModule: Invalid SPIR-V module' at runtime.

## Fix Approach

- - Two-part fix, both upstream in intel/intel-xpu-backend-for-triton (not torch-xpu-ops itself): (1) In triton/backends/intel/driver.py _build / compile_module_from_src, pass '/std:c++20' (and '/Zc:__cplusplus') to the MSVC compiler invocation on Windows, or rewrite driver.c/main.cpp template to avoid designated initializers and lambda captures of constexpr indices so it compiles under the default MSVC C++17 mode. (2) Document and enforce the minimum Intel Arc Windows GPU driver requirement (>=8801 WHQL) for PyTorch 2.13 + Triton 3.7.x in the XPU release notes / installation guide because the new Triton emits SPV_INTEL_predicated_io which only newer drivers understand. - optionally add a runtime driver-version check in the XPU backend that emits a clear error message instead of the opaque 'unknown extension' failure. - No code change is needed in torch-xpu-ops. - track via dependency on the Triton XPU backend fix and driver-version documentation.
