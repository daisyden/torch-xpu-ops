## Root Cause

Test-infrastructure regression in torch-xpu-ops, not a kernel/operator failure. In the current test
tree under third_party/torch-xpu-ops/test/xpu there is no Python XPUUtils definition (nor any
XPUUtils.instance symbol), while failing UTs still expect that singleton-style helper API. Many test
modules share the same import/runtime helper path, so one missing utility attribute fans out to
~2584 failures.

## Fix Approach

- Reintroduce a backward-compatible test helper API in test/xpu/xpu_test_utils.py (add XPUUtils with an instance() classmethod, or alias it to the current XPUPatchForImport flow), then normalize callers to one canonical helper contract.
- Add a focused regression that imports representative XPU test entrypoints on Windows and asserts helper initialization succeeds, so future refactors can't silently remove this compatibility surface.
