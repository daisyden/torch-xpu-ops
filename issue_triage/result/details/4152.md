## Root Cause

The failing UTs exercise FX CSEPass mutation behavior via make_fx on functions including in-place
ops like aten::add_.Tensor. On XPU, tracing hits make_fx's mutable-op restriction and raises
'RuntimeError: Tried to trace mutable operation' before the pass logic can be validated. Rooted in
upstream PyTorch FX tracing semantics for mutable ops, not a torch-xpu-ops kernel bug.

## Fix Approach

- Treat as an upstream-PyTorch dependency: open/track an upstream fix for mutable-op tracing in this CSEPass test path (or functionalize before tracing in the test harness).
- In torch-xpu-ops, keep/mark these cases as XPU skip/xfail with a link to the upstream issue to prevent noisy UT regressions until upstream behavior is corrected.
