## Root Cause

Distributed FSDP MoE timeout on XPU, not a generic single-op bug. The failing pattern concentrates
in MoE configs exercising FSDP sharding/collective-heavy paths (shard_grad_op/none) while no_shard
variants complete and CUDA finishes ~15x faster (20.6s vs 300s timeout), pointing to an XPU-specific
distributed-path stall rather than pure compute cost. The test lives in upstream FSDP parity
coverage; most likely an FSDP+XPU collective scheduling/synchronization interaction. (Related to
#4016.)

## Fix Approach

- Reproduce with a 2-rank minimal FSDP MoE script, add targeted timing/logging around FSDP all_gather/reduce_scatter and rank sync points on XPU, compare against the CUDA timeline to find the first stalled collective.
- Patch the upstream FSDP/XPU integration path (or XCCL invocation ordering if the stall is in backend handoff) to enforce correct stream/event synchronization and collective ordering.
- add an XPU distributed regression asserting completion under shard_grad_op within timeout.
