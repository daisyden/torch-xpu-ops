## Root Cause

Caused by test design, not a softmax correctness bug. The 64-bit-indexing warp softmax case
intentionally creates a very large tensor; on BMG the allocation exceeds available XPU memory during
backward, triggering torch.OutOfMemoryError. Hardware-capacity-bound, expected on lower-memory
configs unless guarded.

## Fix Approach

- Add a BMG-specific (or memory-capability-based) skip/xfail guard for test_warp_softmax_64bit_indexing_xpu_float32, or dynamically reduce the test tensor size based on detected device memory while preserving 64-bit-indexing coverage.
- Keep full-size coverage on higher-memory devices and document the memory threshold.
