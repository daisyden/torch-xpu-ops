## Root Cause

These failures exercise custom-op autograd registration, where tests define _torch_testing::foo,
register only a CPU kernel, register autograd, and expect backward to run
(third_party/torch-xpu-ops/test/xpu/test_custom_ops_xpu.py:2809-2836,2841-2876); the reported
runtime error indicates output lacks grad_fn, meaning the autograd wrapper was not engaged. In
upstream autograd registration plumbing, autograd dispatch should route through Generated.apply when
grads are required (torch/_library/autograd.py:136-150); if dispatch falls through incorrectly,
backward formula is skipped and tensors appear non-differentiable. This points to upstream
custom-op/autograd dispatch behavior rather than a torch-xpu-ops SYCL kernel defect.

## Fix Approach

- Create a minimal isolated reproducer around register_autograd + CPU-only impl under XPU-enabled builds, then verify dispatch key routing reaches the generated autograd impl.
- Fix upstream dispatch/autograd registration interaction (or registration lifetime/state handling if contamination is confirmed), and add a non-flaky regression test that checks grad_fn presence before backward.
