## Root Cause

Functional gap: aten::linalg_matrix_sqrth has no XPU dispatch kernel registered, so functorch/Op
tests hit NotImplementedError. There is no native entry for linalg_matrix_sqrth upstream, consistent
with an xpu-ops-side missing operator path, not a regression. Used by gradient tests, so the missing
forward impl blocks both forward and grad coverage. (This is the root cause behind Phase 2.4's #4169
'no OpInfo / not generated'.)

## Fix Approach

- Implement and register an XPU kernel for aten::linalg_matrix_sqrth in torch-xpu-ops using a numerically stable linalg route (eigendecomposition/SVD) backed by oneMKL where available.
- handle float32 and batched inputs.
- Add OpInfo coverage on XPU and unskip the failing tests once forward+autograd pass.
- If oneMKL lacks the routine, add a temporary decomposition-based fallback and track a follow-up optimization ticket.
