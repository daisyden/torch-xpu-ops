## Root Cause

The failure is an environment dependency mismatch in the test harness rather than an XPU spectral
kernel bug. The upstream ISTFT test calls librosa.istft through test/test_spectral_ops.py:1007 and
compares that reference at test/test_spectral_ops.py:1021 through test/test_spectral_ops.py:1025,
while PyTorch CI pins librosa==0.10.2 for Python 3.12 at .ci/docker/requirements-ci.txt:72. The
issue used librosa 0.9.2 with NumPy 1.26, where librosa still references the removed np.float alias,
so execution fails before validating torch.istft.

## Fix Approach

- Align the Windows XPU test environment with PyTorch CI requirements by installing librosa 0.10.2 for Python 3.12, and add an environment validation/check in the local test setup if needed.
- No torch-xpu-ops source change is required.
