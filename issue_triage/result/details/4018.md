## Root Cause

Likely a regression: #3870 reports fbnetv3_b amp_fp16 training pass on driver 25.40 and
fail_accuracy on 26.19; #4018 reproduces the same signature on Windows BMG/Arc B580. The mismatch
appears in training gradients (bn1.weight.grad), pointing to numerics changing in low-precision
kernel execution, not a harness issue. Strongest dependency is the GPU driver path used by
Inductor-generated fp16 training kernels.

## Fix Approach

- Driver-regression triage: reproduce on the same PyTorch build across known-good vs bad driver versions on BMG Windows, capture per-op/eager-vs-inductor divergence for fbnetv3_b backward around BatchNorm grad, hand a minimized kernel-level repro to the driver team.
- In parallel, test temporary Inductor mitigations (safer accumulation/fallback for the offending fp16 pattern) to unblock release validation.
