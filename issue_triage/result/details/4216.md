## Root Cause

The XPU port hard-codes `RuntimeError` for invalid `torch.linalg.cond` norm types
(`third_party/torch-xpu-ops/test/xpu/test_linalg_xpu.py:709-712`). Upstream changed cond-ord
validation semantics in PR #188591 (file listed by GitHub as
`aten/src/ATen/native/LinearAlgebra.cpp` + `test/test_linalg.py`), so runtime now raises
`ValueError` for this argument check. This creates a pure test-port mismatch: the implementation
behavior changed upstream while the XPU mirror assertion stayed on the old exception type.

## Fix Approach

- Update `test_linalg_xpu.py` to expect `ValueError` in the invalid-ord block, matching upstream test semantics, and run the four dtype variants of `test_cond_errors_and_warnings`.
- Add a small sync note/check in the XPU test-port workflow for exception-type changes in upstream linalg tests.
