## Root Cause

Large batch of FFT-family op tests (fft/ifft/rfft/hfft/irfft and their *n/2 variants across
complex64/128, float32/64, bool) regress on Windows in extended/test_ops_xpu.py between PyTorch
commits 988b354..9b907f1 and torch-xpu-ops 5da2326..0d3b388. FFT on XPU is backed by oneMKL
(SpectralOps via onemkl-sycl-dft); Windows oneMKL DFT path is the failing component. Also
test_mem_get_info regresses (runtime side).

## Fix Approach

- - - - Bisect Windows-only between the two PyTorch / torch-xpu-ops commit pairs. - check if onemkl-sycl-dft version bumped or whether new FFT test parameters were added upstream. - Verify SpectralOps XPU dispatch on Windows and engage oneMKL DFT team if numerical mismatch persists. - investigate test_mem_get_info regression separately as Torch Runtime.
