## Root Cause

The failing test exercises NestedTensor activation checkpointing at
third_party/torch-xpu-ops/test/xpu/test_nestedtensor_xpu.py:7373, including jagged-to-nested
conversion through third_party/torch-xpu-ops/test/xpu/test_nestedtensor_xpu.py:300. PyTorch
checkpoint determinism checking compares saved and recomputed tensor metadata in
torch/utils/checkpoint.py:889 and extracts shape/dtype/device in torch/utils/checkpoint.py:1054,
which exposed a metadata mismatch for NestedTensor subclasses during recompute. The issue was closed
after newer PyTorch and torch-xpu-ops commits, consistent with an upstream checkpoint/NestedTensor
metadata handling fix rather than an XPU kernel defect.

## Fix Approach

- Keep torch-xpu-ops pinned to a version containing the NestedTensor test update and PyTorch to a version containing the checkpoint metadata fix, then rerun test_nested_tensor_activation_checkpoint_xpu.
- If it regresses, compare forward/recompute metadata for the NestedTensor outputs and update the upstream checkpoint subclass metadata handling rather than adding an XPU skip.
