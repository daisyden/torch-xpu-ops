## Root Cause

index_add_xpu_out dispatches directly to native::xpu::index_add_kernel after only device and dim
checks at src/ATen/native/xpu/TensorAdvancedIndexing.cpp:67-83. The implementation in
src/ATen/native/xpu/sycl/Indexing.cpp copies self to result, then uses IndexAddScalarFunctor
atomicAdd(dst, src * alpha) for all dispatched scalar types including Half and BFloat16 (lines
342-352 and 425-459), with only the deterministic-algorithms branch redirecting to index_put_
accumulation (lines 403-411). The dependency lookup maps index_add.out and index_add_ to
Indexing.cpp/SYCL (xpu_supported_operators_complete_list.md:898-899), matching the observed bf16 and
fp32+alpha numerical error to the XPU SYCL atomic accumulation path.

## Fix Approach

- - - - Fix src/ATen/native/xpu/sycl/Indexing.cpp so index_add accumulates with CUDA-compatible precision/order for bf16 and alpha cases, likely by promoting bf16 accumulation or adding a more stable reduction path for repeated indices. - add focused XPU tests mirroring the failing 2D bf16, out-of-place bf16, and fp32 alpha correctness cases.
