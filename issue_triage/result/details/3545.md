## Root Cause

The XPU vmap SDPA test list intentionally appends SDPBackend.CUDNN_ATTENTION even when
get_platform_specific_sdpa() did not report it supported: test/xpu/functorch/test_vmap_xpu.py:95-103
builds the supported list from platform feature flags, then lines 108-110 force-add CUDNN_ATTENTION
for TEST_XPU. The affected tests parametrize over that list at
test/xpu/functorch/test_vmap_xpu.py:3888-3889 and 3942-3944, and run each case under
sdpa_kernel([backend]) at lines 3896-3897 and 3959-3960, so the backend3 case disables viable XPU
SDPA backends and selects a CUDA/cuDNN-only backend.

## Fix Approach

- - - Fix the XPU test port in test/xpu/functorch/test_vmap_xpu.py by removing the TEST_XPU CUDNN_ATTENTION append or filtering CUDNN_ATTENTION out for XPU before parametrization. - keep the MATH/FLASH/EFFICIENT cases that are actually supported and update the dynamic skip entry once backend3 no longer exists.
