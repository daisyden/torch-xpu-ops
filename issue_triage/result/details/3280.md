## Root Cause

test_compare_cpu_addcmul_xpu_{int8,int16,int32,int64,uint8} fail only on Windows nightly (0406). The
XPU integer addcmul path lives in
third_party/torch-xpu-ops/src/ATen/native/xpu/sycl/PointwiseOpsKernels.cpp:48 (addcmul_kernel) and
integer overflow / rounding semantics differ from the CPU reference on Windows, causing assertEqual
mismatches against CPU. Linux runs pass, indicating a Windows-specific MSVC/SYCL codegen difference
in integer multiply-add.

## Fix Approach

- - - - Reproduce on Windows. - compare CPU vs XPU outputs for small int tensors to identify whether the discrepancy is overflow truncation or rounding. - Likely fix is to cast accumulator explicitly (e.g., promote to int64 then cast back) inside AddcmulFunctor in PointwiseOpsKernels.cpp, or align with CPU's wrapping semantics. - Until fixed, keep skipped via skipped_windows label.
