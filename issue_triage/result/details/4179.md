## Root Cause

Failures from upstream XNNPACK-gated tests, not XPU functionality. Upstream classes (e.g.
test_xnnpack_integration.py) are guarded by @unittest.skipUnless(torch.backends.xnnpack.enabled,
'XNNPACK must be enabled... USE_XNNPACK=1'), so a build without XNNPACK should skip, not fail. The
XPU CI runs a test set including these CPU/mobile backend checks while XNNPACK is disabled, causing
false negatives. (In NA sheet as not_target.)

## Fix Approach

- Update the torch-xpu-ops upstream UT selection to exclude/skip XNNPACK-dependent suites when torch.backends.xnnpack.enabled is false (USE_XNNPACK!=1).
- mark not_target.
- Optionally add a CI-side guard/list for known CPU/mobile-only test modules (xnnpack integration / mobile optimizer / jit xnnpack) to enforce skip behavior consistently.
