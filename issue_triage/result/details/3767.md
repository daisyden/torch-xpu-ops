## Root Cause

torch/testing/_internal/distributed/distributed_test.py:7098-7111 validates NCCL execution traces by
requiring exactly three record_param_comms nodes, and lines 7140-7141 further require two allreduce
nodes plus one wait node. In the XCCL backend, src/xccl/ProcessGroupXCCL.cpp:1361-1381 records
allreduce metadata, but WorkXCCL::synchronize at src/xccl/ProcessGroupXCCL.cpp:277-289 only blocks
the stream and does not emit a wait record_param_comms event, so the ported distributed test
observes only two metadata nodes.

## Fix Approach

- Either teach ProcessGroupXCCL wait/synchronize to emit a wait ParamCommsDebugInfo record compatible with the profiler execution trace, or update the distributed test helper to validate XCCL's backend-specific metadata contract instead of reusing NCCL's exact node count.
- Keep the assertion on allreduce metadata fields and add XCCL-specific regression coverage for the wait event if it is implemented.
