## Root Cause

Crash triggered in torch.xpu.graphs.__enter__() before capture begins, when it calls
torch.xpu.synchronize() -> _xpu_synchronize -> c10::xpu::syncStreamsOnDevice, so the fault is in XPU
graph/sync runtime behavior, not _foreach_norm math. _foreach_norm with a very large tensor list is
the reproducer driving runtime into a bad state, but the segfault site indicates a
synchronization/runtime defect (queue/device wait handling).

## Fix Approach

- Treat as an XPU runtime sync bug: build a focused repro around `with torch.xpu.graph(...):` + a large _foreach_norm list and instrument syncStreamsOnDevice (per-queue wait vs device-wide wait) to find the failing backend call.
- Implement a defensive workaround in the XPU graph entry (avoid/limit global device sync in the capture preamble, or route to a safer synchronize path on affected runtime versions), gate by runtime/driver capability, keep the regression test_big_num_tensors__foreach_norm(use_xpu_graph=True).
