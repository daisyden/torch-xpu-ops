## Root Cause

E2E inductor accuracy failure (amp-fp16 training) on timm/sebotnet33ts_256, with divergence in
self-attention positional embedding gradient (stages.1.2.self_attn.pos_embed.height_rel.grad). Same
numeric signature reproduces on Windows and Linux on Arc B580, pointing away from an OS issue toward
a backend codegen/numerics problem in the Inductor low-precision training path. No clear evidence
this is a fresh release regression -> single-case P2 accuracy.

## Fix Approach

- Reproduce with --only sebotnet33ts_256 --backend inductor --training --amp --amp-dtype float16.
- dump/compare Inductor-generated kernels for the failing grad node against eager/fp32 and CUDA baselines.
- enforce fp32 accumulation/casting for the offending reduction path.
- If kernel lowering is incorrect, fix in upstream PyTorch Inductor.
- escalate to Triton-XPU only if the emitted kernel is semantically correct but backend execution is wrong.
