## Root Cause

test_cond_errors_and_warnings_xpu_float64 should exercise Python-level error/warning paths in
torch.linalg.cond, but on Windows XPU it reaches a oneMKL-backed linalg path that dereferences
invalid state and terminates with an access violation. The hard crash (instead of a raised
exception) points to missing backend-side validation/guarding for this dtype/device/platform combo.
Windows + Arc B580 specificity suggests a platform-specific oneMKL/XPU edge case in the cond stack.

## Fix Approach

- Create a minimal repro for torch.linalg.cond(dtype=float64, device='xpu') on Windows and bisect the failing backend call in torch-xpu-ops linalg dispatch to the exact oneMKL invocation.
- Add explicit pre-dispatch validation so error-path inputs raise the intended exception before entering oneMKL.
- add a guarded fallback/skip for the known-bad Windows float64 path.
- Coordinate with oneMKL maintainers on the access violation.
- add a regression asserting exception behavior (no process crash).
