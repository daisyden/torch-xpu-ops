## Root Cause

Active failure is a deterministic tie-breaking regression in XPU topk with many equal values (test
uses all-ones input, expects indices 0..k-1). The XPU topk path doesn't enforce deterministic
tie-ordering: for k>256 it falls back to at::sort(stable=false); for 32<=k<=256 it uses
single-workgroup radix pair sort that is value-ordered but not index-stable. Equal-value elements
return in non-canonical index order, causing assertion mismatches.

## Fix Approach

- Add a deterministic-aware topk path in topk_kernel: under deterministic mode enforce stable tie-breaking by index (value primary, original index secondary) via a stable full sort-and-narrow or stable segmented pair sort.
- gate/disable non-stable optimized sbtopk/single-wg paths under deterministic mode.
- Keep regression coverage for test_topk_deterministic_tie_breaking_cuda_multiblock_xpu (k=128,129,4096).
