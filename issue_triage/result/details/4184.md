## Root Cause

The hang maps to sparse index_select on XPU exercising index_select_sparse_kernel for
sparse-dimension indexing (not the dense path). That kernel does dim_indices.sort() + multiple GPU
passes (IndexSelectSparse1/2/3Functor) and a host sync on intrsc_counts_nneg_index.sum().item();
under the exhaustive large-index test this repeats many times and stalls/takes unbounded time on
BMG. The non-exhaustive sibling completes, consistent with a BMG-specific perf/hang pathology in the
SYCL sparse-index-select pipeline.

## Fix Approach

- Instrument/isolate index_select_sparse_kernel stages on BMG (timing dim_indices.sort(), each functor pass, the sum().item() sync), then gate a safer path: avoid repeated full sorts (cache/reuse sorted indices), add a bounded fallback (CPU/reference or alternative intersection strategy) when sort/intersection exceeds a threshold.
- Add a regression for test_index_select_exhaustive_index_large_xpu_float64 asserting completion within timeout and result parity.
