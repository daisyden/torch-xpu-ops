## Root Cause

The list all_gather path allocates a hidden flattened output at src/xccl/ProcessGroupXCCL.cpp:1644,
runs xccl::onecclAllGather at src/xccl/ProcessGroupXCCL.cpp:1654, then copies each slice back to
user outputs at src/xccl/ProcessGroupXCCL.cpp:1666 without retaining/releasing that temporary in a
way visible to the XPU allocator after empty_cache. The issue was reproduced by a maintainer and
attributed to oneCCL (MLSL-4397), consistent with the temp-sized device-global leak that appears
only after ProcessGroupXCCL all_gather plus torch.xpu.empty_cache.

## Fix Approach

- Track the leak through oneCCL/ProcessGroupXCCL ownership of the flattened temporary, then either land the oneCCL fix referenced by MLSL-4397 or add a ProcessGroupXCCL workaround that uses caller-provided persistent output buffers / explicit temp lifetime synchronization before empty_cache can release memory.
- Add a regression test that loops list all_gather, deletes tensors, calls torch.xpu.empty_cache, and asserts mem_get_info stabilizes.
