## Root Cause

The failure is a CUDA UT porting issue, not an XPU logaddexp kernel failure. The upstream test is
decorated as CUDA-only at test/test_linalg.py:10531 but then hard-codes .cuda() on the complex
inputs at test/test_linalg.py:10536 and test/test_linalg.py:10540; torch-xpu-ops imports and
instantiates that upstream TestLinalg class for XPU at
third_party/torch-xpu-ops/test/xpu/test_linalg_xpu.py:567 and
third_party/torch-xpu-ops/test/xpu/test_linalg_xpu.py:797. On a CUDA-disabled XPU build, the
hard-coded CUDA transfer raises before logaddexp dispatch is exercised.

## Fix Approach

- - Fix the upstream test to use the provided device argument (for example .to(device) or device=device tensors) and keep the CPU comparison path device-agnostic. - then re-enable the XPU port without adding an XPU skip. - No torch-xpu-ops operator change is needed.
