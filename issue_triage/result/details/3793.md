## Root Cause

The XPU pruning wrapper delegates directly to the upstream TestPruningNN class at
third_party/torch-xpu-ops/test/xpu/nn/test_pruning_xpu.py:21, and the failing removal/rollback tests
place full module objects into subTest contexts at test/nn/test_pruning.py:604,
test/nn/test_pruning.py:629, and test/nn/test_pruning.py:744. Under xdist, pytest-subtests sends the
serialized subtest report through execnet, but the context contains torch.nn.modules.linear.Linear,
which execnet cannot serialize. This is a PyTorch test-harness/subTest context bug surfaced by the
XPU port, not a torch-xpu-ops implementation bug.

## Fix Approach

- Change the upstream pruning tests to use lightweight subTest context values such as module type/name and parameter name instead of the module instance itself, or teach the subtest report serialization to sanitize module objects.
- Re-run the three pruning removal/rollback cases with xdist enabled to confirm execnet no longer sees nn.Module objects.
