## Root Cause

PT2E conversion fails in the torchao metadata-porting pass because the pass tries to access
torch.ops.aten.transpose.Dimname, but that overload is not registered in the Python dispatcher. The
ATen schema exists without a dispatch entry at aten/src/ATen/native/native_functions.yaml:6348 while
the comparable transpose.int overload has CompositeExplicitAutograd dispatch at
aten/src/ATen/native/native_functions.yaml:6340, so torch/_ops.py:1239 raises AttributeError during
overload lookup. The C++ implementation is present at aten/src/ATen/native/TensorShape.cpp:3648,
confirming this is a registration/configuration gap rather than a missing kernel.

## Fix Approach

- Add a dispatch section for transpose.Dimname in native_functions.yaml matching the transpose.int registration pattern, regenerate ATen dispatcher code, then validate torch.ops.aten.transpose.Dimname access and rerun the PT2E torchao/Inductor benchmark path.
