## Root Cause

Both failing cases are in the FLASH_ATTENTION path (TestSDPACudaOnly-style coverage), not the oneDNN
OVERRIDEABLE SDPA path. XPU flash support is gated by torch._C._is_flash_attention_available(),
which can allow these tests to run even when specific shape/layout constraints are unsupported,
leading to runtime no-kernel/unsupported behavior. Stock upstream status for at least one case is
skipped with 'XPU Flash Attention is not supported' - a capability-gating mismatch plus remaining
SYCL flash-attn kernel coverage gaps.

## Fix Approach

- (1) Align XPU flash test gating with upstream PLATFORM_SUPPORTS_FLASH_ATTENTION_XPU (or equivalent per-platform capability checks).
- (2) either implement missing SYCL flash-attn support for singleton-head/stride!=1 and head-dim boundary cases, or keep those cases explicitly skipped until kernel support lands.
- Re-run test_transformers_xpu.py for the two cases to confirm skip-or-pass consistency with upstream.
