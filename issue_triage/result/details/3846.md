## Root Cause

Failing XPU ported tests inherit upstream logic that hardcodes torch.cuda-specific APIs instead of
device-generic utilities, so tests that should validate generic-accelerator behavior fail on XPU due
to harness/device assumptions, not kernel correctness. Affects convolution and indexing - a
recurring test-porting pattern, not an isolated op bug.

## Fix Approach

- Patch affected upstream tests to replace direct torch.cuda calls with device-agnostic helpers (current device/type queries, stream/sync/memory via framework abstractions) and gate CUDA-only paths explicitly.
- Validate by rerunning the named XPU tests + a sweep for similar hardcoded torch.cuda usage in related modules.
- upstream the fixes and pull into torch-xpu-ops sync.
