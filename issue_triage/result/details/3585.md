## Root Cause

The failing assertion checks that a leaf tensor's gradient stride matches the leaf stride in
test/test_autograd.py:13787-13805, so the observed stride (0, ...) indicates grad layout enforcement
was disabled before this test ran. The upstream root cause is that enforce_grad_layout_policy(False)
sets the global grad-layout enforcement flag in __init__ at torch/autograd/grad_mode.py:392-395, but
unlike set_grad_enabled at lines 185-192 and _force_original_view_tracking at lines 432-439, it has
no __call__ override to restore the previous flag when used as a decorator; __exit__ only restores
context-manager usage at lines 397-401. The torch-xpu-ops issue comments point to
pytorch/pytorch#183867 and PR #183868 for this non-XPU-specific global-state leak.

## Fix Approach

- - - Land the upstream PyTorch fix adding enforce_grad_layout_policy.__call__ that restores torch._C._set_grad_layout_enforcement_enabled(self.prev) before delegating to super().__call__. - After that, unskip/re-enable the XPU autograd test. - no torch-xpu-ops kernel change is appropriate.
