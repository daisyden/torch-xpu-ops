## Root Cause

The failing UT is an Inductor fusion test, but it exercises F.scaled_dot_product_attention backward,
which dispatches on XPU to sycltla::flash_attention_backward
(aten/src/ATen/native/transformers/xpu/attention_backward.cpp) into the SYCL flash-attn backward
kernels (third_party/torch-xpu-ops/.../flash_attn/sycltla/mha_bwd*.cpp). On PVC with LTS-driver
wheels this path shows bf16/half numerical drift exceeding test tolerance, so it's a precision
mismatch, not a fusion-logic bug. Per taxonomy precedence -> Flash Attention.

## Fix Approach

- Reproduce with the same PVC + LTS wheel matrix and isolate SDPA backward numerics by toggling flash-attn off/on.
- patch the SYCL flash-attn backward path (accumulation/casting or kernel variant selection in mha_bwd*.cpp) to reduce error on PVC, and add a targeted XPU regression for this SDPA-backward precision case.
- If kernel-side correction is blocked, add a guarded fallback in XPU SDPA dispatch (sdp_utils.cpp) to avoid flash-attn backward on affected PVC+driver combos.
