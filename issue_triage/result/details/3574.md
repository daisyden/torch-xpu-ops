## Root Cause

The OpInfo entries for nn.functional.conv_transpose2d and conv_transpose3d list generic dtypes and
CUDA-specific dtypes but no dtypesIfXPU override at
torch/testing/_internal/common_methods_invocations.py:16295-16305 and 16350-16359. The issue/CI
reports that torch.int8 works on XPU forward but is missing from the OpInfo, causing
TestCommonXPU.test_dtypes to fail; the operator lookup maps conv_transpose2d and conv_transpose3d to
Copy.cpp with SYCL/+oneDNN dependency at xpu_supported_operators_complete_list.md:843-846.
torch-xpu-ops source search finds no conv_transpose implementation under src, only tests/references,
which supports that this is upstream OpInfo metadata lagging backend behavior rather than a failing
XPU kernel.

## Fix Approach

- - - Update the upstream OpInfo definitions for nn.functional.conv_transpose2d and conv_transpose3d in torch/testing/_internal/common_methods_invocations.py to add dtypesIfXPU=floating_and_complex_types_and(torch.bfloat16, torch.float16, torch.int8). - Then run the targeted TestCommonXPU.test_dtypes cases and remove the temporary skip once the dtype metadata matches actual XPU forward support.
