## Root Cause

In TorchDynamo tracing, zip(..., strict=True) inside DefaultsTests.test_zip_strict raises a
ValueError during symbolic execution and is wrapped as torch._dynamo.exc.Unsupported. The test
passes in stock eager, so the breakage is in Dynamo graph capture/guarding, not an XPU kernel.
Dynamo is not handling strict-zip length semantics correctly for this path, causing an avoidable
graph break on XPU UT.

## Fix Approach

- Reproduce with dynamo/test_functions_xpu.DefaultsTests.test_zip_strict.
- patch upstream TorchDynamo bytecode/tracing for zip(strict=True) so equal-length checks are represented in guards or deferred to runtime without raising Unsupported.
- Add a targeted Dynamo unit test for strict-zip (mismatch + equal-length).
- unskip the XPU mirror once the upstream fix lands.
