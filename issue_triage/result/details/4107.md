## Root Cause

The decomposition for aten.adaptive_max_pool2d in torch/_decomp/decompositions.py is partially
implemented and returns NotImplemented for the general non-evenly-divisible case. In the XPU decomp
cross-ref harness, decomp output is flattened and compared against the real op arity; NotImplemented
becomes a single leaf while the real op returns (output, indices), triggering assert
len(real_out)==len(decomp_out). Same contract-mismatch pattern as #3890 across 12 cases.

## Fix Approach

- Upstream should make adaptive_max_pool2d decomposition total: every control path returns a 2-tuple (values, indices) with correct semantics (including the non-evenly-divisible branch), or avoid registering the decomposition until complete.
- Extend decomp cross-reference tests to cover non-evenly-divisible output sizes asserting tuple arity + index correctness.
