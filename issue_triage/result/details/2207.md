## Root Cause

Tracker for incomplete FP8/MXFP8 enablement on XPU, not a single defect. Support is fragmented
across many eager ops and FP8 variants (e4m3fn/e4m3fnuz/e5m2/e5m2fnuz/e8m0fnu), needing CUDA
alignment for casting/promotion/op semantics. GEMM coverage (_scaled_mm/_scaled_grouped_mm) depends
on upstream XPU pathways and backend kernel support, so end-to-end FP8 parity is blocked by missing
upstream dtype/operator plumbing.

## Fix Approach

- Drive as a staged enablement matrix: first land upstream FP8/MXFP8 dtype + dispatch/meta coverage needed by XPU, then implement/enable missing XPU memory+eltwise ops, finally close GEMM gaps (_scaled_mm/_scaled_grouped_mm) with backend integration and CUDA-parity tests per dtype variant.
