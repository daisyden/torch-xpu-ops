## Root Cause

Failure occurs before any XPU-op kernel: torch.UntypedStorage(*args, device=device) rejects a Python
list[int] in test_untyped_storage_meta_xpu ('item was of type int instead of int'), pointing to a
regression in the UntypedStorage constructor/type-parsing logic (or its Windows XPU build path) on
release/2.13 for LNL Windows. Passed on LNL PT2.12 and BMG PT2.13 -> a platform/build-specific
runtime regression, not torch-xpu-ops test logic.

## Fix Approach

- Upstream runtime bug: reproduce with a minimal script on LNL Windows PT2.13 (torch.UntypedStorage([1,2,3], device='xpu') + cpu/meta controls), bisect/cherry-pick around storage-constructor parsing changes 2.12->2.13.
- Patch the UntypedStorage sequence argument parser/binding for Windows XPU builds, add a regression for list-based UntypedStorage construction on XPU/meta in upstream test_torch.py, backport to release/2.13.
