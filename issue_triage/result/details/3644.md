## Root Cause

The failing tests all exercise the deprecated torch._custom_ops explicit-autograd path in
test/xpu/test_custom_ops_xpu.py:1356-1469 and 2048-2070. The custom-op autograd indirection is
registered only to the generic Autograd key in torch/_custom_op/impl.py:162-167, while
torch/_custom_op/impl.py:354-356 only checks CPU/CUDA autograd keys and never accounts for
AutogradXPU; on XPU this lets the backend autograd fallback at
aten/src/ATen/core/VariableFallbackKernel.cpp:70-72 intercept before the generated custom-op
backward, so outputs do not get the expected grad_fn and y.backward() reports that the tensor does
not require grad.

## Fix Approach

- - - Fix the upstream PyTorch custom-op autograd registration/check path to cover AutogradXPU (and ideally all backend autograd keys rather than the CPU/CUDA-only list), then unskip/re-enable the XPU TestCustomOp backward cases in torch-xpu-ops after the upstream fix is vendored. - Add a focused XPU regression for a custom op with impl_save_for_backward plus impl_backward proving the generated backward runs and validation errors are preserved.
