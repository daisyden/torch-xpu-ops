## Root Cause

The failing HopSchema ScriptObj tests call init_torchbind_implementations() then
load_torchbind_test_lib() from torch/testing/_internal/torchbind_impls.py, which hard-requires
libtorchbind_test.so on Linux, but that shared library is not present/discoverable in the
Release/2.13 XPU test environment. A test artifact/build packaging gap (the lib is produced by
PyTorch C++ JIT test build targets), not a HOP logic regression.

## Fix Approach

- Infra fix: ensure torchbind_test (libtorchbind_test.so) is built and shipped in the test environment and visible to find_library_location/runtime loader.
- Short-term unblock: gate or xfail the three ScriptObj-dependent HopSchema tests when the torchbind test lib is unavailable, tracking the packaging fix in PyTorch test infrastructure.
