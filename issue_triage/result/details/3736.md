## Root Cause

The regression is isolated to Inductor cold-start inference benchmarks:
benchmarks/dynamo/common.py:3731 enables fresh Triton cache measurement and
benchmarks/dynamo/perf_cli.py:1413 appends --performance --cold-start-latency for benchmark
commands. Eager and training remain stable while Triton 3.7.1 produces 10-20x slower Inductor
inference on PVC, and the issue has already been moved to intel-xpu-backend-for-triton#6992, so the
root cause is Triton XPU codegen/scheduling rather than torch-xpu-ops operator code.

## Fix Approach

- Bisect Triton between the baseline 21033c4e2be build and target 2bafaf80, then inspect generated Triton kernels for the affected depthwise/mobile inference graphs for excessive launches or slower scheduling.
- Fix should land in intel-xpu-backend-for-triton, followed by rerunning the torchbench/timm_models --inference --backend=inductor --cold-start-latency PVC benchmarks to confirm ratios return near baseline.
