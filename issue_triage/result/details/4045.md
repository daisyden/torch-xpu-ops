## Root Cause

Crash in the XPU device-availability path invoked by torch.xpu.is_available() on Arc under WSL2 - a
safe probe that instead dereferences invalid state during runtime/driver init. Points to a low-level
failure in the Intel GPU runtime stack (Level Zero/driver path on WSL2), not Python API misuse. A
segfault on a core capability check is release-blocking.

## Fix Approach

- Reproduce on ARC-WSL2 with symbols and collect a native backtrace from the is_available() probe.
- harden PyTorch's XPU availability check to treat runtime init/query failures as a non-fatal False return (with error logging) instead of crashing.
- Add a regression that forces runtime init failure and verifies no segfault.
- Escalate to Intel driver/runtime owners with the minimal repro + stack to fix the underlying Level Zero/driver bug.
