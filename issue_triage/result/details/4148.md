## Root Cause

Request to enable the existing _spsolve sparse operator on XPU, but XPU dispatch/registration is
missing; _spsolve is a sparse linear solve currently wired for CPU/CUDA sparse dispatch, so XPU
falls through to no implementation. Sparse solve is typically provided by vendor sparse-linalg
libraries, so XPU support depends on integrating the oneMKL sparse solver path and matching PyTorch
sparse CSR semantics. An operator implementation gap, not a regression.

## Fix Approach

- Add XPU dispatch registration for _spsolve in native_functions.yaml/backend wiring, implement the XPU kernel using oneMKL sparse-solve APIs for CSR inputs (including left behavior), align behavior/errors with CPU/CUDA semantics.
- Add correctness, shape/dtype/device checks, and fallback/error-path coverage in sparse tests.
- gate on oneMKL availability with clear diagnostics when unsupported.
