## Root Cause

New stateless RNG operators are wired only for CUDA upstream: _philox_key_split,
_philox_key_fold_in, _philox_normal_, _philox_uniform_ have CUDA dispatch but no XPU dispatch; the
stateless impl files are CUDA-specific (aten/src/ATen/native/cuda/PhiloxKeySplit.cu, CUDA philox
helpers), with no XPU native kernel. XPU cannot execute the new stateless uniform/normal path even
though it has Philox state support for stateful RNG.

## Fix Approach

- Enable XPU backend in upstream PyTorch: add XPU dispatch for the four _philox_* ops in native_functions.yaml and implement XPU SYCL kernels (key split/fold-in + uniform_/normal_ from stateless Philox key tuples), reusing existing XPU Philox utilities but keeping the path purely key-driven (no mutable generator state).
- Add/port backend tests asserting functional correctness and determinism on XPU for identical keys across calls/shapes.
