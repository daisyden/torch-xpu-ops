## Root Cause

The XPU tests assert the older CUDA-era FakeTensor failure surface (RuntimeError 'Unhandled
FakeTensor Device Propagation'). Current upstream FakeTensor raises FakeTensorDeviceMismatchError (a
RuntimeError subclass) with 'Expected all tensors to be on the same device...'. An
API/diagnostic-alignment drift in exception type/message expectations, not a functional kernel bug.

## Fix Approach

- Align torch-xpu-ops FakeTensor mismatch tests with upstream: update assertions to accept FakeTensorDeviceMismatchError (or RuntimeError subclass) and match the canonical 'Expected all tensors to be on the same device' text.
- If strict CUDA/XPU parity is required, patch upstream FakeTensor error normalization first then mirror in XPU tests.
- otherwise treat as a test-expectation update tracked as an upstream-pytorch dependency.
