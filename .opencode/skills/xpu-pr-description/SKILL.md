# XPU PR Description Drafting

Produce a PR description for an agent-authored XPU fix in the house style used by
PRs like pytorch/pytorch#202187. Keep the human-written parts blank; put the AI
analysis in a collapsed `<details>` block.

## Inputs to gather

1. **Target PR** (`gh pr view <num> --repo <owner/repo> --json title,body,files,commits,additions,deletions`)
   — read the commit message / existing body for the root cause, fix, and test plan.
2. **Reference PR** whose format to mirror (fetch its body for the exact headings).
3. **Linked issue** (often an intel/torch-xpu-ops issue) — read it for the repro,
   version context, and the list of failing **cases**.

## Template

```markdown
## Linked issue or supporting maintainer

Fixes <owner/repo#NNNN>

Related cases:

​```
<only the case strings tied to THIS PR, e.g.
op_ut,third_party.torch-xpu-ops.test.xpu.test_X.ClassName,test_method>
​```

## BC-breaking?

No   <!-- or Yes + explanation -->

## Summary (human written only)

### Background

<!-- TODO (human): fill in -->

### Solution

<!-- TODO (human): fill in -->

## Agent details (if applicable)

The analysis below was generated by an AI assistant (Claude via OpenCode).

<details>

> **Root cause.** ...
>
> **Fix.** ...
>
> **Alternatives rejected.** ...
>
> **Repro.** <commands / before-after table>
>
> **Test status.** <what was verified and how>

</details>

cc @gujinghui @EikanWang @fengyuan14 @guangyey
```

## Rules

- **Leave `Summary (human written only)` empty** — only `Background` / `Solution`
  stub headings with a TODO comment. The human fills these.
- **Related cases: list ONLY the cases tied to this PR.** An issue may enumerate
  many cases; include just the one(s) this PR actually fixes. Use the exact case
  string from the issue (`op_ut,<module path>,<Class>,<test>`).
- **All AI analysis goes inside `<details>`**, each point prefixed with `> ` as a
  blockquote. Lead with a one-line disclosure sentence above the block.
- **BC-breaking?** default `No` unless the change alters exported behavior.
- Keep the `cc @...` line matching the reference PR's maintainers.

## Avoid redundancy in Agent details

- Don't ship two near-identical command blocks (a "Repro" block and a "Test
  status" block running the same commands) — keep one.
- Don't restate the before/after table in prose right next to it.
- Drop JSON fields not referenced by the fix (keep only the keys the code reads).
